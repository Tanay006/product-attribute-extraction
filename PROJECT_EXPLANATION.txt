PROJECT EXPLANATION
===================

Project title
-------------
Product Attribute Extraction using spaCy NER and Streamlit

One-sentence explanation
------------------------
This project is an interactive NLP application that reads clothing product
descriptions and automatically extracts four product attributes: sleeve style,
neckline, length, and pattern.


1. Problem statement
--------------------
Online clothing descriptions contain useful product information in free-form
text. Important attributes are not always stored in separate database fields.
For example, the description:

    "Women's black floral maxi dress with short sleeves and a V-neck"

contains several attributes:

    PATTERN      -> floral
    LENGTH       -> maxi
    SLEEVE_STYLE -> short sleeves
    NECKLINE     -> V-neck

The purpose of this project is to identify these attribute phrases
automatically, so that unstructured product descriptions can be converted into
structured information for search, filtering, catalog management, and analysis.


2. What the application does
----------------------------
The application is built with Streamlit and has two main pages.

Page 1: NLP Model + Attribute Extraction

    - Accepts one clothing product description as input.
    - Removes only leading and trailing whitespace.
    - Tokenizes the text using spaCy's English tokenizer.
    - Sends the text to the trained spaCy NER model.
    - Highlights recognized entities in the original description.
    - Groups the results by attribute.
    - Displays the entity text, character positions, and token positions.
    - Allows the results to be downloaded as JSON or CSV.
    - Can load a random record from the test set.
    - Can compare a model prediction with the record's gold annotation.
    - Supports batch extraction for many descriptions.
    - Provides word-removal, or occlusion, explainability.

Page 2: Model Evaluation + Audit

    - Displays precision, recall, and F1 metrics.
    - Shows strict exact-span scores and lenient overlapping-span scores.
    - Shows per-attribute performance.
    - Shows subgroup results such as short versus long descriptions.
    - Shows error analysis and recurring prediction errors.
    - Shows training history and validation curves.
    - Shows audit findings and possible missing gold labels.
    - Provides downloads of generated evaluation files and reports.

The application does not create fake predictions or fake metrics. It uses the
real trained model and real files generated by the project's evaluation
scripts.


3. NLP technique used: Named Entity Recognition
------------------------------------------------
The main machine-learning task is Named Entity Recognition, commonly called
NER.

NER normally identifies entities such as people, organizations, locations, or
dates. In this project, the entity labels are custom product attributes:

    SLEEVE_STYLE
    NECKLINE
    LENGTH
    PATTERN

The model learns to find the beginning and continuation of each attribute
phrase in a product description. The training labels use the BIO format:

    B-LABEL -> beginning of an entity
    I-LABEL -> continuation of an entity
    O       -> outside any entity

Example:

    Text:   "A floral dress with long sleeves"
    Labels: O O B-PATTERN O B-SLEEVE_STYLE I-SLEEVE_STYLE

The model predicts both:

    1. The span of text that is an entity.
    2. The attribute label assigned to that span.

This is span classification rather than simple keyword matching. Therefore,
the model can learn context and can identify multi-word phrases such as
"three quarter sleeves" or "boat neck".


4. Data used by the project
---------------------------
The data is divided into three files:

    data/train.json -> used to train the model
    data/val.json   -> used during training for validation and model selection
    data/test.json  -> held out for final evaluation

Each record contains information such as:

    - Original product text
    - Token list
    - BIO labels
    - Product category
    - Length group

The data split prevents the model from being evaluated only on examples it has
already seen. The test set is kept separate so that the final metrics better
represent performance on unseen descriptions.

The project also contains data/labels.txt, which lists the supported labels.


5. Training and model files
---------------------------
The training code is in train.py. It creates a blank English spaCy pipeline,
adds an NER component, registers the four labels, and trains on the annotated
records.

The shared data and label conversion utilities are in common.py. This file:

    - Loads the JSON records.
    - Converts BIO token labels into character spans.
    - Aligns spans with spaCy token boundaries.
    - Creates spaCy Example objects.
    - Creates a blank NER model with the four labels.

The trained model is saved in the model/ directory. Important files include:

    model/config.cfg
    model/meta.json
    model/tokenizer
    model/ner/
    model/vocab/

The application loads this saved pipeline at startup. It verifies that the
directory exists, that it is a valid spaCy pipeline, that it has an NER
component, and that it contains all four expected labels.

The model location can be changed with the NER_MODEL_DIR environment variable.
The default location is model/ next to app.py.


6. Preprocessing
----------------
The model was trained on raw product text using spaCy tokenization. The
application therefore applies the same preprocessing at inference time.

The application:

    - Strips leading and trailing whitespace.
    - Uses spaCy's English tokenizer.
    - Preserves original capitalization.
    - Does not lowercase the input.
    - Does not remove stop words.
    - Does not perform stemming.
    - Does not perform lemmatization.

Keeping training and inference preprocessing consistent is important. If the
input were changed significantly before prediction, the model could receive a
different type of input from the data on which it was trained.


7. End-to-end application workflow
-----------------------------------
The runtime flow is:

    User enters product description
             |
             v
    Text is trimmed and tokenized
             |
             v
    Saved spaCy NER pipeline processes the text
             |
             v
    Entity spans and labels are returned
             |
             v
    Entities are grouped into four attributes
             |
             v
    Results are displayed, highlighted, and downloadable

The main files involved are:

    app.py
        Streamlit entry point. Sets the page configuration and navigation.

    views/extraction_page.py
        User interface for text input, prediction, batch processing,
        gold comparison, and explainability.

    views/evaluation_page.py
        User interface for metrics, errors, subgroups, audit results,
        training curves, and downloads.

    pipeline.py
        Model loading, validation, preprocessing, prediction, batch
        extraction, gold comparison, and dataset summaries.

    common.py
        Shared constants, data loading, BIO-to-span conversion, and
        spaCy training-example creation.

    ui.py
        Reusable visual components, CSS, cards, tables, highlighting,
        layout helpers, and chart styling.

    results.py
        Loads evaluation outputs and runs the evaluation pipeline from the UI.

    evaluate.py
        Calculates spaCy scorer metrics and writes files to outputs/.

    predict_spacy.py
        Generates predictions for the test set.

    audit.py
        Produces audit tables, charts, error files, and a Word report.

    explain.py
        Implements word-removal occlusion analysis.

    tests/smoke_test.py
        Renders both Streamlit pages headlessly and checks for exceptions.


8. Evaluation methodology
-------------------------
The project uses entity-level evaluation rather than simple text-level
accuracy.

Precision:
    Of all entities predicted by the model, how many were correct?

Recall:
    Of all entities present in the gold annotations, how many did the model
    find?

F1 score:
    The harmonic mean of precision and recall.

Strict exact-match scoring:
    A prediction is correct only when both the attribute label and the exact
    entity span match the gold annotation.

Lenient scoring:
    A prediction is counted when it has the same label and overlaps the gold
    span, even if the boundaries are slightly different.

Micro averaging:
    All entities are pooled before calculating the metric. This gives more
    influence to labels with more examples.

Macro averaging:
    Metrics are calculated separately for each attribute and then averaged.
    This gives each attribute equal importance.

The application also evaluates performance by attribute and by subgroups such
as short and long product descriptions. This helps identify whether the model
works equally well across different types of input.


9. Error analysis and auditing
------------------------------
The audit pipeline checks more than one overall score. It generates:

    - Overall results
    - Per-attribute results
    - Subgroup results
    - Entity-property results
    - Detailed prediction errors
    - Possible missing gold labels
    - Training curves
    - Charts
    - A Word audit report

This is useful because a single F1 score does not explain why a model fails.
For example, a model may perform well on LENGTH but poorly on NECKLINE, or it
may struggle with long descriptions even if its overall score is acceptable.

The application also warns when:

    - Evaluation files do not exist.
    - Results appear to come from a stand-in or preview model.
    - The model is newer than the saved evaluation results.


10. Explainability
------------------
The project uses word-removal occlusion analysis as a simple explainability
method.

The procedure is:

    1. Run the model on the complete input.
    2. Remove one word.
    3. Run the model again.
    4. Compare the new entities with the original entities.
    5. Record which attributes disappear.

If removing a word causes an attribute to disappear, that word contributed to
the model's prediction for that attribute. This does not prove causality, but
it gives a practical indication of which words the model relied on.


11. Important limitations
-------------------------
The model only extracts four attributes:

    - Sleeve style
    - Neckline
    - Length
    - Pattern

It does not currently extract brand, color, size, material, price, or other
product properties.

spaCy's NER component does not provide a calibrated confidence score for each
entity in this implementation, so the application does not display confidence
values.

Some gold labels in the dataset are incomplete. Consequently, a prediction
that is not present in the gold labels is not automatically a true model
mistake. The audit page reports this data-quality issue.

Some product categories have relatively few test records. Their subgroup
metrics should therefore be interpreted carefully.

The model may fail on wording, spelling, or product styles that are very
different from the training data. NER performance depends heavily on the
quality, coverage, and consistency of the annotations.


12. How to run the project locally
-----------------------------------
From the project directory:

    python -m venv .venv

Windows PowerShell:

    .\.venv\Scripts\Activate.ps1

Install dependencies:

    pip install -r requirements.txt

Run the application:

    streamlit run app.py

Open the local URL shown by Streamlit, normally:

    http://localhost:8501

To leave the virtual environment:

    deactivate


13. How to train and evaluate
-----------------------------
If the trained model is not available, a quick training run can be used for
sanity checking:

    python train.py --quick

For full training:

    python train.py

Generate the evaluation outputs:

    python evaluate.py

Generate test-set predictions:

    python predict_spacy.py --model model --test data/test.json --out predictions.json

Generate the audit outputs:

    python audit.py --preds predictions.json --model-name "spaCy NER"

The Streamlit evaluation page can also run these three steps in order using its
"Run evaluation + audit now" button.


14. Deployment
--------------
The application is a Streamlit server, so Streamlit Community Cloud is the
most suitable simple deployment option.

Deployment steps:

    1. Push the project to GitHub.
    2. Open share.streamlit.io.
    3. Select the GitHub repository.
    4. Select the main branch.
    5. Set the application file to app.py.
    6. Deploy.

The repository should include:

    app.py
    requirements.txt
    model/
    data/
    views/
    .streamlit/config.toml

The .gitignore excludes the local .venv directory, Python caches, and generated
evaluation outputs. The source code, model, and data remain available for
deployment.

Vercel is not the natural platform for the current application because this
project uses a persistent Streamlit process and Streamlit's interactive
connection model. To use Vercel, the application would need to be redesigned
as a web frontend plus a FastAPI or Flask backend.

16. Short presentation script
-----------------------------
"Our project is a product attribute extraction system for clothing
descriptions. We trained a custom spaCy Named Entity Recognition model on
annotated product text. Instead of extracting general entities such as people
or locations, our model identifies four domain-specific entities: sleeve style,
neckline, length, and pattern. The annotations use the BIO format and the data
is divided into training, validation, and test sets.

The user interface is implemented in Streamlit. A user enters a product
description, the application applies the same preprocessing used during
training, and the saved spaCy pipeline predicts entity spans. The results are
highlighted in the text, grouped into structured attributes, and available as
JSON or CSV.

The second page evaluates the model using precision, recall, exact-match F1,
lenient overlap-based F1, per-attribute results, subgroup analysis, and error
analysis. We also included word-removal occlusion to show which words affect
the predictions. The system reports real model outputs and does not use
placeholder metrics. Its main limitations are that it supports only four
attributes, spaCy does not provide confidence scores in this setup, and some
gold labels are incomplete."


17. Likely professor questions and answers
-------------------------------------------

Q: Why did you use NER?
A: The task requires finding labeled spans inside free-form text. NER is
designed to locate and classify spans, and it naturally supports custom labels.

Q: Why not use keyword matching?
A: Keyword matching is less flexible. It can miss spelling and context
variations, cannot naturally learn multi-word entities, and is harder to
generalize to unseen combinations.

Q: Why are train, validation, and test sets separate?
A: Training fits the model, validation helps select or monitor the model, and
the held-out test set provides a more independent performance estimate.

Q: What is the difference between precision and recall?
A: Precision measures how many predictions are correct. Recall measures how
many gold entities were found. F1 balances both.

Q: What does exact-match evaluation mean?
A: Both the label and the complete character span must match the gold entity.
Even a slightly different boundary can be marked incorrect.

Q: Why can lenient F1 be higher than strict F1?
A: Lenient scoring accepts the same label when the predicted span overlaps the
gold span. This shows whether some errors are only boundary errors.

Q: What happens if the model folder is missing?
A: The application displays a clear setup message instead of inventing
predictions. The model can be trained or copied into model/.

Q: What is the purpose of the audit page?
A: It goes beyond one score by showing per-label behavior, subgroup behavior,
recurring errors, possible annotation problems, and generated reports.

Q: What would you improve next?
A: I would add more consistently labeled training data, support additional
attributes, evaluate on more product categories, add confidence calibration,
and expose the model through an API for integration with a catalog system.


18. Final conclusion
--------------------
This project combines supervised NLP, custom entity labels, model
interpretability, evaluation, and an interactive web interface. It
demonstrates how a trained NER model can convert unstructured clothing
descriptions into structured product attributes while also showing its
performance and limitations transparently.
